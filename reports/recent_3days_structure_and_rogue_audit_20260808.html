04 / What improved

结构整理取得了可验证的正面结果

最大的收益不是文件名变整齐，而是模式根不再拥有几乎全部实现。

Root reduction

三个关键根显著缩小

普通模式从 3,003 行降至 973 行（−67.6%）；塔防从 6,742 行降至 1,042 行（−84.5%）；mp_game.gd 从 14,901 行降至 5,099 行（−65.8%）。

Mode isolation

模式间没有直接路径反向依赖

对 standard、tower_defense、rogue 三个目录的静态扫描，没有发现它们互相引用对方的 res://scene/game_modes/… 路径。

Composition

场景仍承担真实组合

协调器以原生场景节点和信号组合，主要迁移保留了 .tscn 与 .uid，没有把整个结构转成脚本内动态生成。

Data boundary

模式定义和加载入口集中

GameModeDefinition 保存单人/多人入口、运行时、战役和加载权重，主菜单、加载器和多人大厅共享同一模式目录。

Shared domains

共享能力得到明确落点

伤害、状态、反馈、对象池、导航、投射物进入 scene/combat；背包、合成、资料与升级 UI 进入 scene/ui/shared。目录意图已经清楚，但 collectibles 与 Boss 的一处反向依赖仍需解除。

Regression safety

重构伴随契约与 AB 测试

最近新增 71 个 dev GDScript，其中 43 个 smoke test、20 个 probe、7 个 fixture，为继续拆分保留了行为基线。

06 / Implemented in worktree

HUD component

顶部 HUD 已成为独立原生场景

Visual direction

中部继续显示“浅层矿洞”，标题现由当前 FloorDefinition 经 set_floor_title() 注入。

Floor boundary

第一版 FloorDefinition 已建立

shallow_mine_floor.tres 集中持有 floor_id、display_name、generation config、world metrics、背景和默认 combat config。RouteGame 在父节点 _enter_tree() 中先完整验证，再向 Board、背景、TopBar、简报与战斗协调器注入；各子场景不再保存楼层默认值，简报和协调器引用同一战斗资源。

runtime / content hash 已分离，且不通过 FileAccess 读取 raw PNG；专用 smoke test 已以 exit 0、无 ERROR、无泄漏通过，并覆盖无效定义整体拒绝。这里解决的是楼层配置的原子应用，尚不等于 P0 的全量联机快照原子提交。

新增或替换节点图时只需修改对应 .tres，测试也已经切换到现行 128×128 素材。

Asset cleanup

旧节点与旧世界素材已清理

删除 11 个被 V3/V4 替代的 PNG 及其 11 个 import：旧六类节点图、旧空节点、旧 HUD panel/seed、旧连接图块和旧地面图块。

Test contract

07 / Expansion gates

P0 / P1 / P2 风险与退出条件

优先级按“是否会让即将添加的内容形成错误事实源或不可恢复网络状态”划分，而不是按文件大小排序。

P0

光石没有权威账本

当前只有 set_shared_light_stone_amount() 的 UI 入口，代码注释明确说明持久化和结算尚未进入 RunState。地下商店、馈赠或节点奖励一旦读写光石，就会出现 Host、客户端、晚加入与跨场景事实不一致。

退出：建立 PartyLightStoneLedger，Host 独占 credit/debit，带 revision、全量快照、晚加入和跨路线/塔防持久化测试。
P0

全量快照缺少原子提交层

路线布局、RuntimeState、briefing、encounter、玩家与账本由多个子快照和信号拼装。部分字段校验失败时，必须保证旧状态完整保留，不能留下“新图 + 旧位置”或“已扣 AP + 旧遭遇”的混合版本。

退出：所有子快照先 stage 和交叉校验 schema / contract hash / revision，再一次 commit，并只发出一次聚合 state_changed。
P1

FloorDefinition 第一版已建立，内容层仍不完整

浅层矿洞资源已经收拢身份、标题、生成配置、世界指标、背景和默认战斗，并提供分离的 runtime/content hash。但 ambient VFX、节点 handler / encounter registry、音乐与内容池 manifest 尚未成为楼层目录；EncounterRegistry 的签名也尚未进入 runtime contract。

退出：扩充现有楼层资源与注册表，而不是复制路线场景；runtime contract 纳入会影响权威结果的 encounter registry 签名，并以第二个楼层资源证明无需修改 RouteGame。
P1

缺少 Node Handler 注册边界

节点视觉已数据化，但 RouteGame 仍以类型分支决定首次进入、回访、简报和内容启动。四类待实现节点会让模式根继续膨胀。

退出：按 type_id/content_pool_id 注册 handler，统一 can_enter、preview、begin_authoritative、revisit 与 snapshot 接口。
P1

遭遇选择缺少独立 Resolver

遭遇 session、overlay、经济协调器和 RouteGame 共同承担选项、投票、表现与效果。继续添加随机遭遇会把 UI、随机性和权威经济写入同一流程。

退出：Resolver 以 encounter_id、seed、参与者和选项产生确定性的效果命令；UI 只展示，账本只执行命令。
P1

Rogue 仍使用 test_arena_p3 协议身份

文件结构已正式 Rogue 化，但 mode_id=4、wire_key 和 lobby label 仍属于测试场 P3。GameModeCatalog 明确说明这些编号属于 v46 wire contract，直接改名会影响联机和潜在存档。

退出：定义正式 Rogue 身份、旧 key alias 和版本迁移；固定旧房间/快照兼容测试后再调整大厅文案。
P1

RunState 仍是经济总仓

run_state.gd 约 2,851 行、131 个函数，同时持有本地/多人库存、升级、共享仓库、个人息壤、核心生命、状态惩罚、全量经济快照和多组 revision/CAS。若直接把光石继续加进去，新的共享货币会与既有六类事实共享同一个高冲突 Autoload。

退出：拆出 InventoryLedger、UpgradeLedger、WarehouseLedger、PartyXirangLedger、PartyStatusLedger 与 PartyLightStoneLedger；Autoload 只保留生命周期 facade 和聚合快照。

共享 collectibles 与 Boss 形成依赖环

combat/collectibles/collectible_sakura_rocket.tscn 直接使用 Linglan Boss 的 skill2 rocket 脚本；该 Boss 脚本又以 CollectibleSakuraExplosion 依赖共享收藏品实现。共享 combat 因而反向知道具体 Boss，目录边界与编译加载边界不一致。

多人组合根仍偏向塔防

mp_game.gd 已大幅缩小，但仍硬加载 Tower Economy、World、Fate 协调器；mp_game.tscn 也直接实例化这些模式节点。新增模式仍需修改全局多人根。

退出：由模式 session/adapter 提供专属 coordinator bundle，全局 MpGame 只组合共享协议服务。
P2

预加载与对象池清单仍硬编码

GameModeCatalog.TOWER_DEFENSE_PRELOAD_RESOURCE_PATHS 仍是全局脚本中的大型路径数组；combat_runtime_base.gd 与 wave_combat_runtime_base.gd 也直接 preload 具体敌人弹体/VFX，并硬写 retained capacity。增加敌人、植物或模式资源仍要修改共享运行时代码。

退出：建立 PreloadManifest 与 ContentPoolManifest Resource，由 GameModeDefinition/FloorDefinition 引用；加载器和对象池只解释路径、预热量、保留量与上限。
08 / Recommended sequence

继续扩展 Rogue 的安全路线

先补事实所有权，再加新节点内容；先用现有两类正式流程证明接口，再迁移其余类型。

冻结当前路线契约

保留 Graph、RuntimeState 和现有快照字段；为首次访问、回访、AP 扣除、briefing 和 encounter 建立固定 seed 契约测试。不要同时改协议字段与视觉。

扩充已建立的 FloorDefinition

保留现有 floor_id、generation config、world metrics、背景和默认战斗边界；继续加入 ambient VFX、节点/遭遇 registry、音乐与内容池 manifest，并把会改变权威结果的 registry 签名纳入 runtime contract。以第二楼层资源验证 RouteGame 无需新增条件分支。

拆分 RunState ledger，并建立光石与原子快照 staging

先把库存、升级、仓库、息壤和队伍状态的事实所有权从 2,851 行 Autoload 拆出，再实现 Host 权威共享光石；把 layout/state/briefing/encounter/ledger 的完整快照变成 validate → stage → commit。

提取 NodeContentRouter 与 Handler

先把现有 NormalCombat 和 MagicalEncounter 迁成 handler，确保行为不变；再新增 EmergencyCombat、UndergroundShop、Gift 和 WildernessResource，避免一次性改六种流程。

分离 EncounterResolver

让 session 只维护参与者和阶段，overlay 只显示，resolver 只从 seed/选项生成效果命令，ledger/runtime 执行命令并写入 revision。

收缩 RogueRouteGame

依次迁出 RouteSessionCoordinator、RoutePlayerCoordinator、RouteContentCoordinator；根脚本只保留生命周期、组件接线和场景级呈现开关。

最后处理正式协议身份和多人组合根

以版本化 alias 迁移 test_arena_p3；再让各模式 session 提供专属多人 coordinator 和 preload manifest，避免将协议迁移与玩法重构混在同一提交。

解除共享层反向依赖并资源化内容池

将樱花弹等 Boss/collectible 共用实现下沉为中性战斗构件；把共享 runtime 中的具体敌人弹体、VFX 和池容量迁入 ContentPoolManifest。以“scene/combat 不引用具体 boss/mode”为结构验收。
