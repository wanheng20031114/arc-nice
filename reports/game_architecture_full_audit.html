Executive findings

最先处理的，不是文件大小本身

真正决定风险的是所有权和时序：谁能修改事实、谁复制了一份规则、哪些工作在同一帧集中发生、哪些网络入口被错误地视作权限边界。

P0

正式多人协议保留两个任意客户端可调用的作弊 RPC

CH6 上可请求 Host 增加 1,000 息壤或添加白名单收藏品，没有 debug build、房主或权限开关。公开联机前必须从正式注册表删除或强制开发权限。

P0

铃兰技能 1 的弹幕规模足以主导物理帧

静态推导约 360 发/秒、每轮约 6,120 发、稳态约 720 发同时在场；对象池解决了分配，却没有消除每弹 Area2D、脚本和世界射线。

P1

Game 与塔防根脚本拥有 117 个文本完全相同的函数

至少 1,320 行精确重复，覆盖波次、Boss、音乐、多人实体注册等。修复在两个模式间漂移的概率，已经高于“继承层次不够优雅”这种风格问题。

P1

伤害、状态和 source type 有多个事实源

基础减伤公式复制三份；DamageType 错挂在 EnemyConfig；元素状态规则又在敌人、投射物与 MpGame 中以字符串和魔法数镜像。

P1

标准模式仍有 0.35 秒一次的同步全量重定向尖峰

对每个敌人遍历玩家，形成 O(E×P) 齿形；塔防已经有每物理帧最多 16 个的预算式版本，可以上移复用。

P2

大型协调器不是立刻重写的理由，却是先建立契约测试的理由

MpGame 11,990 行、Player 4,610 行、GameTD 5,089 行。先锁定伤害舍入、状态时序、revision、实体 roster 与 RPC 表面，再按所有权拆分。

阅读口径：本报告是全仓静态源码审查，不是新采集的 CPU/GPU/网络实测。所有“低/中/高”性能评级都来自调用频率、算法复杂度、节点/查询数量、池化与预算结构；只有在明确写出“静态推导”时才给出估算值。

资源事实层

06 / Items & inventory

物品不是一条系统，而是四条使用链

PickupConfig 同时承载立即拾取 Buff、可入库材料、不可堆叠建筑物品和收藏品效果。报告按“获得 → 存放 → 消费 → 多人事务”追踪，而不是只罗列资源名。

世界事件

敌人默认掉落表逐条独立掷骰；Pickup 没有逐帧逻辑，使用 lifetime + blink Timer。Host 先尝试即时应用，失败再尝试入背包。

20 槽背包 / 仓库网络

资源路径定义同一物品；材料与药瓶可叠，建筑和收藏品不可叠。revision + request ID 保护使用、丢弃、合成与多人重放。

消费与效果

临时 Buff 立即应用；材料进入 17 条配方/2 项研究；建筑箱以 CAS 消耗后放置；收藏品由 Player 事件入口解释。

Relay parity、运维与已明确不支持的能力

RPC parity

主项目 102+9 与 Relay stub 102+9 静态相等，测试比较注解/签名/信道。当前有 11 个没有网络发送点的遗留/本地 decoder 壳仍增加表面积。

公网生命周期

游戏内返回大厅没有 DELETE；dead Relay Popen 记录不主动 reap，房间/端口可最长残留 10 小时。首个 ENet 连接者直接成为 authority。

能力边界

不支持 late join、断线重连、Host migration；identity 等于本次 peer ID，没有 account/session/reconnect token 或 repair cut-over barrier。

遥测口径：MultiplayerRuntimeMetrics 能记录 8 信道 packet/payload、最大包、repair、不完整 batch 和事务 p95，但 payload diagnostics 默认关闭；开启后也只是 var_to_bytes 抽样估算，不是 ENet/UDP 真实线速。缺 RTT、loss、retransmit、可靠队列深度、per-peer 带宽、jitter 与 correction magnitude。
P0

作弊 RPC 在正式表面

任意已加入客户端可请求 Host 增加 1,000 息壤，或向背包加入白名单收藏品；服务端没有 build/role/permission gate。

P0

公网大厅关房接口无令牌

leave 只凭公开 player_name；使用房主名会删除房间并停止 Relay。Host token 没有覆盖这个破坏性操作。

P0

公网控制面仍是 HTTP + 匿名创建

Host token、续租与状态更新走硬编码明文 HTTP。匿名创建没有认证或速率限制，可占满 100 个、最低 10 小时存活的 Relay 进程。

P1

投射物命中参数可信，几何证明不足

Host 重建伤害与属性，但普通客户端命中报告不验证投射物与目标的时空接触；穿透弹可对不同敌人各提交一次。

P1

玩家受击仍采用客户端上报结果

部分来源由本地目标先应用再回报，Host 使用客户端报告的受击后生命，而非对所有攻击独立重算。

P2

CH5 可靠队列职责过宽

大地形快照、实体生灭、流程/基地、植物状态和时序敏感动作同信道；大修复期间可能出现队头阻塞。

能力边界：现有修复服务于已经进入本局的客户端；断线重连与中途加入被明确拒绝，Host 断开即结束且没有 Host migration。不能把“有完整状态修复”写成“支持 reconnect”。
