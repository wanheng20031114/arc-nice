# 新敌人端到端集成检查表

`SKILL.md` 是流程规范；本文只提供参数模板、证据结构和按影响面启用的检查项。若两者产生冲突，以主流程为准并修正文档漂移。

## 任务契约模板

每次任务填写本节中的参数槽位。不要把某次答案写回通用 Pipeline。

### 身份与视觉

- 稳定 ID、显示名、分类和阶级；
- 世界体量、原生帧尺寸、注册点和默认朝向；
- 核心轮廓、材质、主色、功能色、持物和禁止元素；
- 新敌人还是派生版本；若为派生版本，列出必须逐字节或逐行为继承的内容；
- 需要的人审门：主视觉、动画、可选特效、最终候选。

### 动画

对每个动作记录：

- 动画名和用途；
- 帧数、运行 FPS、循环方式；
- 主体允许变化与必须稳定的区域；
- 前摇、锁向、伤害和恢复对应的帧或时间；
- 进入、退出和相位切换规则；
- 左右镜像或多方向资源策略。

### 玩法

- 生命、攻击、防御、速度、基地伤害和奖励；
- 接触伤害、主动攻击、投射物、召唤物或状态能力；
- 身体碰撞、接触区域、攻击查询与视觉附件的边界；
- 冷却、范围、角度、目标选择、去重与墙体语义；
- 特殊承伤、免疫、倍率或死亡规则在结算链中的位置；
- 掉落表及分类标签是否会带来现有副作用。

### 联机

- Host 唯一执行的逻辑；
- 代理端只需表现的内容；
- 可复用的动作、快照位、elapsed 补播和乱序保护；
- 是否真的需要新 RPC、频道、状态位、投射物类型或攻击 ID；
- 中途加入、死亡、断线重连和旧快照的语义。

### 集成

- 图鉴排序与分类；
- 普通/精英替换或派生映射；
- 允许直接引用该敌人的模式、波次或遭遇；
- 必须保持零直引的内容；
- 需要预热、池化或加载屏障的资源；
- 网络可见资源合同与协议版本影响。

### 非目标

明确本次不实现的能力和不允许变化的公共接口。非目标是防止实现范围膨胀的合同，不是以后偷偷补 fallback 的借口。

## 阶段与证书

推荐状态链：

~~~text
concept_pending
→ anchor_approved
→ animation_pending
→ animation_approved
→ final_pending
→ final_approved
→ runtime_written
~~~

有独立特效门时插入对应的 pending/approved；简单任务经用户同意可合并门，但不得把未确认状态直接标为批准。

### Manifest

Manifest 保存批准语义，建议至少包含：

~~~yaml
stage: <current-stage>
approvals:
  anchor:
    selection: <selection-or-null>
    approved_by: <user-or-authority>
    evidence_ref: <message-or-record-reference>
    candidate_file_sha256: <sha-or-null>
    candidate_decoded_sha256: <sha-if-raster-or-null>
  animation:
    selection: <selection-or-null>
    approved_by: <user-or-authority>
    evidence_ref: <message-or-record-reference>
    candidate_file_sha256: <sha-or-null>
    candidate_decoded_sha256: <sha-if-raster-or-null>
  final:
    approved: <true-or-false>
    approved_by: <user-or-authority>
    evidence_ref: <message-or-record-reference>
    candidate_file_sha256: <sha-or-null>
    candidate_decoded_sha256: <sha-if-raster-or-null>
inputs:
  - path: <project-relative-path>
    file_sha256: <sha>
    decoded_sha256: <sha-if-raster>
outputs:
  - path: <project-relative-path>
    file_sha256: <sha>
    decoded_sha256: <sha-if-raster>
runtime:
  written: <true-or-false>
  paths:
    - path: <project-relative-path>
      file_sha256: <sha>
      decoded_sha256: <sha-if-raster>
build:
  certificate_owner: <single-tool-or-role>
  builder_sha256: <sha>
  deterministic_passes: <count>
  drift_count: <count>
~~~

字段名可以适配现有工具，但必须能回答：批准了什么、基于哪份输入、生成了什么、是否写过运行时。

Canonical manifest 只由 `certificate_owner` 更新。Preview builder 和 runtime writer 分别输出不可变的阶段报告或发布报告，再由证书所有者顺序吸收；两者不得直接并发改写 canonical manifest。

### Report

Report 保存可复算事实：

- 文件尺寸、模式、帧数和运行 FPS；
- 调色板、alpha、边距、bbox、注册点和连通性；
- 每帧文件/像素哈希；
- 镜像、切换、伤害帧和碰撞叠加的审计结果；
- 运行场景、配置、导入和测试结果。

Report 不能代替用户批准，也不能把没有验证的预期写成通过。

### Stability

- 对同一输入至少完整构建两次；
- 快照范围必须写清楚；
- 自引用的证书文件若不进入自身哈希快照，要明确排除原因；
- 两轮输出和当前磁盘文件必须一致；
- 构建过程中若文件仍在变化，立即停止审计，等待唯一写入者冻结后从头复算。

## 视觉门交付物

本节仅在视觉发生变化且没有可复用批准素材时启用。复用既有批准素材或用户明确跳过视觉门时，在 manifest 中记录来源和依据即可。

### 主视觉

每案单独提供：

- ImageGen 原稿及来源哈希；
- 像素目标的原稿必须本身为最终 native 像素画，或能证明为统一整数倍展示；提供 native 1:1 与整数倍 nearest-neighbor 视图，高细节概念图不能代替像素锚点；
- `grid_evidence_mode` 只能是 `direct_native` 或 `exact_integer_display`。前者记录原稿/最终尺寸及零空间重采样证明；后者记录最终 native 尺寸、全帧共用的方形整数倍率、逻辑画布、格距、格相位、主体逻辑 bbox、每格 Alpha/调色板唯一性、源格与 native 格基数、`max_sources_per_native=1`、`dropped=0`、`duplicated=0` 和分析工具 SHA；
- 明确断言所有帧使用相同倍率和相位。逐帧 scale/origin、固定 scale 整格投票、覆盖率/多数票、`bounded_jitter_partition`、边缘拟合、最小特征宽度、地标评分与拓扑相似只能写入诊断报告，不能写成发布证据；`native_or_unknown` 也不能代替正向整数格证明；
- 发生逻辑像素超标或整数格失败重绘时，记录 `derived_from`，并证明实际 ImageGen 调用默认只携带已批准主视觉锚点；动作由完整逐帧 prompt 重新声明，不得传入失败动作稿。保存输入的文件/解码 SHA、实际 prompt、输出 SHA 和 lineage；若用户明确授权第二张动作参考，再逐项记录授权与用途。Prompt 必须要求严格一致的 native 画布、格距、格相位、主体尺度与脚底锚点；旧下游候选与证书失效，新稿回到 pending 并重走人工门；
- 透明或规范化参考；
- 原生候选和严格整数倍最近邻放大；所有审阅板与 GIF 禁止非整数展示缩放；
- 原稿到原生候选的空间操作清单与逐像素差异记录。直接 native 不得空间重采样；统一整数展示只能把已证明颜色/Alpha 一致的整数块逐格一对一解码，不得调用 resize/downsample；
- 记录头/眼、手/握点、脚底、透明分隔和武器端点的原稿→native 状态。地标与拓扑审计只在整数格通过后检查语义正确性，不能补救或放行混合格；
- 分开记录严格整数格证明与 padding/裁切覆盖率；后者不能作为像素周期、格距或相位证明；
- 分开审计 Alpha 与描边：Alpha 不得由覆盖率/多数票补回，描边只能在已有 Alpha 边界上按来源证据规范化；分别列出外轮廓和封闭负空间边界，禁止用降低阈值或膨胀掩盖破损；
- 成对功能色提供左右局部 ROI/mask/色族合同；禁止盲镜像。任何人审 recolor-only 例外必须数据驱动、SHA 锁定、before/after 明确且 Alpha 变化为 0；
- 正向与精确镜像；
- 轮廓、注册点、身体碰撞和攻击范围叠加；
- 与项目内相近体型单位的尺寸对照。

多案必须有实际轮廓、比例、面部或持物差异，不能只换颜色。
多手或多武器角色还必须逐件记录手、握点、武器所在身体侧和连接关系；“数量正确”或“整体连通”不能代替空间关系正确。

### 动画

每个动作方案单独提供：

- 独立 ImageGen 调用证据：批准主视觉锚点的文件/解码 SHA、完整 prompt、输出 SHA，以及输入图像清单；默认输入清单只能有该主视觉；
- 未输入旧动画 sheet、压缩稿、native 尝试、点表稿或其他动作的否定断言。若用户明确批准额外动作参考，逐项记录授权和用途；
- 跨多个 sheet 的同一动作分别记录每次调用，同时证明它们锁定同一主视觉 SHA、身份、镜头尺度与帧语义；
- 未经空间处理的 ImageGen raw 人工审阅图；在 raw 获批前不得把压缩、下采样、补点或重画结果列为候选；
- 原生 strip 或逐帧资源；
- 正向和镜像 GIF，全部使用 native 或严格整数倍 nearest-neighbor 展示；
- 相对批准锚点的逐帧差分；
- 主体稳定、附件连接和帧唯一性报告；
- 动画所有帧的统一 native 画布、整数倍率、格距和格相位证书；直接 native 分支记录零空间重采样；
- 运行 FPS、GIF 审阅时基和循环方式的独立记录。

检查“看起来在走”或“挥击有力”等审美问题时，必须观看实际 GIF；检查帧数、FPS 和伤害时刻时，必须读取运行资源。

### 最终候选

- 完整 atlas 或最终帧清单；
- 每个动作的独立正反向预览；
- 移动到前摇、前摇到攻击、攻击到恢复/死亡的串联；
- 攻击跟踪与锁向示意；
- 左右碰撞/查询叠加；
- 世界尺寸对照；
- source-to-final 零差异或白名单差异证书。
- 所有 atlas、GIF、串联和对照板使用 native 或整数倍 nearest-neighbor；禁止把诊断 resize 产物混入最终候选。

最终候选仍是 preview。批准前 runtime.written 必须为 false。

## 运行时决策

### 复用还是新增

依次判断：

1. 现有配置是否已能表达；
2. 现有行为族是否只缺一个默认关闭的参数或虚方法；
3. 派生脚本是否可以只实现差异；
4. 只有状态机语义真正不同，才新增独立行为实现。

不要复制整套状态机来改变一个伤害来源名、一个动画名或一个参数。

### 场景结构

- 新增节点类型或不确定场景结构前先查 Godot 官方文档；
- 直接在 .tscn 中声明节点、形状和资源引用；
- 身体世界碰撞只表达身体；
- 接触伤害区不因视觉武器而扩大；
- 主动攻击查询与预警使用同一几何参数；
- 纯视觉附件不撞墙，也不偷偷参与接触伤害；
- 持久状态切换要冻结身体、接触区、查询、预警和视觉节点的启停顺序；
- AnimatedSprite2D 的默认朝向与原生素材一致；
- Atlas 边缘帧使用 filter_clip，避免串帧。

### 方向与伤害时序

对每种攻击写清楚：

~~~text
追踪目标 → 提交目标 → 前摇跟踪方向 → 锁定方向 → 伤害帧查询 → 恢复
~~~

每一步可以按玩法删减，但不能含糊。测试至少覆盖：

- 原生朝向下武器位于视觉前方；
- 镜像后武器、预警和查询共同翻转；
- 锁向前目标跨侧时是否跟随；
- 锁向后目标绕后时是否保持方向并合法落空；
- 目标离开距离/角度后不产生幽灵命中；
- 伤害帧、音效和视觉挥击处于同一动作阶段。

### 公共接口

- 新字段和钩子默认关闭；
- 特殊承伤只处理已通过合法性、权威性和正伤害判定的命中；
- 批量结算必须保持逐命中语义；
- 共享掉落继承必须防重复和循环；
- 修改公共基类后，运行原型敌人的回归测试。

## 集成决策

### 图鉴与计数

从仓库现值推导新计数，更新注册表、分类、阶级、纹理审计和依赖这些总数的专项测试。不要复制旧计划中的数字。

### 投放范围

列出唯一允许引用的内容，然后对其他范围做零直引检查。这样可以防止测试敌人意外进入正式波次，也能防止正式敌人只存在于图鉴而从未投放。

### 协议

在最终同步远端后再决定版本：

1. 读取主项目当前版本；
2. 读取 Relay 实现与 `relay_servers/README.md`；
3. 检查并行功能是否已占用计划版本；
4. 需要升级时使用当前基线的下一版本；
5. 原子更新所有“当前版本”断言与 `relay_servers/README.md`；
6. 保留历史说明和拒绝旧版本测试；
7. 验证频道、RPC 表面、快照位和攻击 ID 是否真的需要变化。

资源合同变化可能需要版本升级，但不能顺手扩大协议表面。

## 分层测试矩阵

按影响面启用，不要求小改动跑无关宽测试。

| 层级 | 启用条件 | 检查内容 |
| --- | --- | --- |
| 素材 | 纹理、动画或导入变化 | 尺寸、帧数、FPS、loop、alpha、调色板、锚点、安全区、连通、镜像、导入 |
| 属性 | 配置、分类、奖励或掉落变化 | 配置值、分类、奖励、掉落和派生关系 |
| 行为 | 状态机、攻击或冷却变化 | 状态切换、冷却、范围、伤害帧、取消、死亡清理 |
| 承伤 | 伤害结算或特殊承伤变化 | 物理、法术、DoT、批量、倍率、无视、防御后零伤、致死、死后请求 |
| 碰撞 | 形状、导航或攻击几何变化 | 身体、接触、攻击几何、边界角度/距离、墙体、水域、导航、目标去重 |
| 方向 | 镜像、跟踪或锁向变化 | 原生前方、左右镜像、前摇跟踪、挥击锁向、绕后/出距合法落空 |
| 联机 | 联机行为或网络可见资源变化 | Host 唯一结算、代理零伤害、重复/乱序/迟到、持久状态中途加入、旧快照 |
| 集成 | 图鉴、掉落、模式、波次或加载变化 | 计数、投放、派生映射、预热和零直引 |
| 协议 | 资源合同、wire、RPC 或 Relay 变化 | 当前版本、Relay parity、旧版本拒绝、频道/RPC/ID 不变量 |
| 回归 | 修改或复用公共能力 | 被复用行为族、公共结算、掉落继承和原型敌人 |

测试应聚焦影响面。宽测试若有已知基线失败，要用同一远端基线和定向结果区分，不得直接忽略。

## 必须停止的情况

出现以下任一情况，不要继续下一门：

- 用户选择不明确或证书仍为 pending；
- 多个进程正在写同一产物；
- builder、report、manifest 或输入哈希漂移；
- ImageGen 参考像素未经批准进入原生运行素材；
- 像素目标的原稿本身不是清晰像素画，或原生候选依赖对概念稿的主观重画；
- 原稿既不是直接 native，也不能证明所有帧共享同一方形整数倍率、逻辑画布、格距和格相位；
- 任一帧需要独立 scale/origin、存在 mixed-cell/边缘跨格，或构建依赖 resize、downsample、整格投票、固定比例适配或 many-to-one；即使特征、地标和拓扑看似保留也必须停止；
- ImageGen 重绘没有实际携带已批准主视觉锚点、擅自传入失败动画/压缩稿，或新稿尚未重新通过人工门；
- 单点采样、颜色量化或 Alpha 处理使头/眼、手/握点、脚、武器、透明分隔或轮廓发生变化；
- 运行 FPS 与 GIF 时基混用；
- 角色锚点、附件连接、默认朝向或攻击方向不一致；
- visual、warning 和 damage query 使用不同几何；
- 代理端执行了权威伤害或状态推进；
- 需要人审的视觉分支在最终批准前出现对应运行资源写入；
- 计划协议版本已被远端占用；
- Rebase 冲突只保留一侧而丢失另一侧语义；
- 验证进程失控或无法确认是否由本任务启动。

修复后必须基于静止的新快照从头复算相关阶段，旧证书和旧审计结论作废。

## 最终交付检查

### 发布前

- 视觉变化时，最终批准或既有批准素材复用依据已记录；
- 需要发布素材时，writer 无参数应拒绝写入，显式发布成功且幂等；
- 资源变化时，Godot 导入成功；
- 所有受影响层级和必要回归通过；
- git diff --check 通过；
- 没有冲突标记、绝对本机路径、临时文件或未解释的大文件。

### 远端同步

本节只在用户明确要求同步、提交或推送时启用：

- 先保护现有用户改动，再 fetch 最新远端；
- 必要时保存可恢复备份并 rebase；
- 重新推导计数和协议版本；
- 冲突后重跑受影响的测试；
