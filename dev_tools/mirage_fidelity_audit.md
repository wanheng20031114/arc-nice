# Mirage 2D 复刻检查

检查日期：2026-09-07。状态：**检查完成，地图重建尚未实施**。

当前地图尚未达到 CS2 Mirage 复刻要求。它保留了主要分区的大致方位，但路线、门窗边界、高低层关系、掩体形状与美术投影均有明显偏差。先前以联网功能、全图连通和安全出生检查通过作为完成依据，不足以证明复刻质量。

## P1：直接影响路线与对枪的错误

### 1. A1 门拱堵住主通路

`scene/pvp/maps/mirage_map.tscn:4113` 的 `ARampArchLeft` 碰撞矩形为 `(1429.6, 1080.2, 16.5, 92.4)`。该段通道地面纵向范围为 `1088..1184`；柱底 `1172.6` 至南墙仅余 **11.4 px**，角色碰撞圆直径为 **14 px**。

在局部范围 `(1344,1040,224,184)` 内，从 `(1400,1136)` 至 `(1480,1136)` 进行 1 px 网格、真实圆与矩形距离的通路检查：半径 7 不可达；半径 5 对照可绕柱底通过。跨 `x=1438` 的净空截面也证明正常角色不能通过。全图仍可绕其他路线抵达 A 点，因而原来的全局可达性检查没有发现缺失的 A1 路线。

原因：`dev_tools/build_mirage_map.py:257`、`:265` 把四处不同朝向的门拱统一生成相同朝向的两条长柱，且将正面立面的柱高当成俯视占地长度。

### 2. 下水道、VIP、梯子房与中路的边界被合并

`build_mirage_map.py:82` 至 `:84` 的区域相交，`:118` 至 `:120` 又补入连续地面，把本应区分高度或明确门洞的区域并入同一可走平面。当前场景存在以下无障碍直线，射线和半径 7 的角色均可通过：

| 当前连接 | 世界坐标起点 → 终点 | 影响 |
| --- | --- | --- |
| 梯子房 → 下水道 | `(703.2,660)` → `(775.2,660)` | 跨层空间没有隔离 |
| VIP → 下水道 | `(672,770)` → `(775.2,770)` | 房间侧壁变成直接出口 |
| 梯子房 → 猫道 | `(732,726)` → `(936,726)` | 通道经过已合并的下水道平面 |
| VIP → 中路 | `(816,825)` → `(919.2,825)` | 窗口被改成可双向步行的台阶 |

2D 改编可以改变高度的表现方法，但需要保留连接位置、穿越条件和视线关系。当前做法会同时改变转点、守点与交叉火力。

### 3. 超市与 VIP 之间的薄墙消失

对照原版雷达，`build_mirage_map.py:83` 的 VIP 描摹范围已经向西扩大，与超市之间的建筑隔断被严重压缩；`:83` 与 `:85` 的区域之间仅剩 4 个参考像素的间隔，即 9.6 世界单位。`:108` 仅按 32 px 地面格中心决定是否铺地，`:142` 再把所有非地面格作为墙体，最终连这道残余薄墙也没有留下。问题同时来自描摹范围错误和格子化，不能只靠减小格子修复。

当前从超市 `(540,820.6)` 到中路 `(1068,820.6)`，一条 **528 px** 的直线可以贯穿 VIP，角色和子弹均无阻挡。该错误形成了不应存在的直通射界。

超市至 B 点的地面接口还扩成 224 px，公寓南侧接口扩成 160 px。装饰门拱并没有重建原版门、窗、窗台与平台的独立边界。这两处宽度是当前场景事实，不能单独作为原版实际门宽的测量值。

## P2：明显降低地图辨识度的问题

### 4. 整图比例与建筑轮廓由格子决定

`build_mirage_map.py:23` 使用横向 `2.4`、纵向 `2.2` 的非等比缩放，相对参考图横纵比例相差约 **9.1%**。一格对应约 `13.33 × 14.55` 参考像素，足以吞掉薄墙、窄门和小平台。

`:188` 从可走区域向外扩三格生成可见建筑，`:205` 用坐标范围决定蓝墙、屋瓦或米色纹理，`:225` 用统一 7 px 线条画边缘。建筑主体由通路网格反推，而非依据 Mirage 的建筑轮廓搭建；斜墙、门框、窗沿、平台和楼梯因此被矩形台阶化。

### 5. 标志性掩体未做对应造型

- `build_mirage_map.py:157` 至 `:161`：A 点 Triple、Firebox、Tetris 使用同一箱堆素材；Ticket 使用 `market_stall` 市场摊位素材。
- B 点中央棚架与多柱结构未建立，仅放置通用箱子和一根孤立石柱。公寓出口、平台、白车与中央掩体缺少原版的组合关系。
- 中路箱子、A 点掩体、B 点掩体共用少量通用图片和矩形体积，改变可藏身边缘、露头角度和地点辨识。

用户提出的“不受规整瓦片限制”只在少量道具节点上落实，尚未用于关键建筑和独特掩体。需要单独制作这些形状，而不是增加通用道具数量。

### 6. 像素密度与投影不统一

- 地面材质的 313 源像素压到 32 世界单位，约 **9.78 源像素/世界单位**。
- A Default 道具约 **4.03 源像素/世界单位**。
- 角色采用未缩放的 32 × 32 像素动画，并使用 nearest 过滤。
- 门拱为正面立面，箱堆为斜俯视，地毯为倾斜平面，其他物件更接近鸟瞰；它们直接混放于正交俯视地面。

结果是细密材质、平滑道具与大像素角色不属于同一画面体系。整组石板和楼梯缩成小格后反复铺贴，也制造了密集重复纹理。无 HUD、无迷雾的全图仍存在此问题，不能归因于界面或视野效果。

### 7. 道具落地轮廓与碰撞/视野边界不对应

Tetris 贴图约 `69 × 80.5` 世界单位，碰撞仅 `54 × 44`；A Default 贴图约 `73 × 71.8`，碰撞为 `54 × 50`。两个矩形均居中，未表达斜视图的底座、侧面和高度偏移。

精灵图片可以包含超出落地碰撞的屋顶或高度部分，但需要明确的投影规则。当前没有这样的统一规则，A 点实机图可见矩形遮罩横切斜视箱堆。视野算法依据现有碰撞工作，不能自行纠正地图轮廓错误。

## 重建顺序与验收条件

1. **先重建通路和边界。** 以原版雷达定位，结合原版结构核对，逐区列出普通步行、跳落、窗台和上下层连接。采用等比世界尺度，墙体与门洞独立于地面瓦片；优先解决 A1 堵路、超市薄墙和下水道重叠。
2. **再重建标志性结构。** 分别制作 A 点 Default / Triple / Tetris / Ticket、B 点棚架 / 公寓平台 / 超市门窗、中路 VIP 窗口等独立场景。明确外轮廓、开口、落地碰撞与遮挡关系。
3. **统一视觉标准后重新绘制素材。** 固定俯视投影、角色相对尺寸、像素密度、光照方向和建筑高度表现；生成与最终显示尺寸匹配的地面及特殊物件。仅按原生 Alpha 切分、裁边和打包。
4. **增加局部路线与禁止连接的检查。** A1、A2、拱门、B 小、公寓等必需通路分别验证；超市→VIP、梯子房→下水道等不应平面直通的边界分别验证。检查使用真实角色体积与墙体碰撞，不能只验证两队出生点能互达。
5. **按区检查实机画面与对枪空间。** 全图及 A/B/中路局部对照；验证门洞净空、关键掩体的可绕行侧、露头位置与遮挡。最后再回归多人选队、买枪、丢枪和战斗规则。
